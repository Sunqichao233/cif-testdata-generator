  user             user01     API_filter    user01     user01     user01
  password         4wxL…      DWIG…         4wxL…      4wxL…      4wxL…
  type             ns         ns            ns         ns         ns
  inputpath        C:/common/tools/AIScoringExport/ （5ファイルとも同一）
  outputpath       aml01      aml02         aml01      aml02      aml03
  retrysec         600        600           600        600        600
  retrycount       5          5             5          5          5
  boundaryString   Oculus…xxxxyz （5ファイルとも同一）

  ★ 実際にお客様設定値が入っているのは 横東aml02（東日本銀行）の1ファイルのみ。
     他の4ファイルは hostname/user/password が PKGテンプレートのまま
     （http://127.0.0.1:8081 ／ user01 ／ 5ファイル中4ファイルで同一の
     パスワード）で、ヒアリングシート2部の値と一致しない。
     outputpath だけはスキーマ別に正しく振られているため、
     配備スクリプトでスキーマ別の雛形は生成されたが、
     接続情報の設定作業が aml02（東日本）以外で行われていないと推測される。

  ★ inputpath が5ファイルとも「C:/common/tools/AIScoringExport/」で、
     設計書 I列の「C:\common\tools\AIScoringExport\amlXX\export\」と異なる。
     5ファイル共通の差異のため、個別の設定ミスではなく
     ・プログラム側でスキーマ名を付加している
     ・設計書の記載が実装より細かい
     のいずれかと推測。要確認。

  ★ パス区切りが資材は「/」、設計書は「\」。ディレクトリは同一のため実害なし
     （表記揺れとして突合表では別扱いにしている）。

■ AIScoringImport.properties（全スキーマ共通・1台に1ファイル）
───────────────────────────────────────────────
  connectstring  （RDSエンドポイント）:5432/amldb　※実エンドポイントが設定済
  password       8Mrb…（計24桁）

  → 設計書 properties設定一覧(AML) 行192-193（横東）／行287-288（陸道七）
  → connectstring：E列（PKG標準）は localhost:5432/amldb だが、
     I列（調整後）が「（RDSエンドポイント）:5432/amldb」＋
     J列備考「DBサーバではなくRDSにDB構築しているため」。
     資材はI列の指示どおり実エンドポイントが設定されており、整合している。
  → password：設計書 E列の値と完全一致。
     ※この値は設計書上の26個のpropertiesファイル全てで共通のPKG標準値。
  ★ 同名ファイルは properties設定一覧(SIM) にも存在するが、SIM側はI列が空
     ＝有効値は localhost:5432/amldb。AML側とSIM側で有効値が異なるため、
     資材の採取元サーバ（AML／SIM）を要確認。
  ★ 修正履歴 項番25「SimulationControl.properties の connectstring を
     RDSエンドポイントからローカル接続に変更」との整合も要確認。
