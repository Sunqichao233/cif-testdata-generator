作成日：2026/11/06
宛先　：小島さん
対象　：共同機構接続（AIスコアリング）　properties 設定ファイル
突合表：成果物\【横東】設定ファイル_環境定義書、資材突合せ.xlsx
　　　　成果物\【陸道七】設定ファイル_環境定義書、資材突合せ.xlsx

突合の方法
　①環境定義書_設定ファイル「properties設定一覧(AML)」の有効値
　　（I列「調整後の値」があればI列、無ければE列「パッケージ標準設定値」）
　②V5.0 現地リリース資材の properties 実物
　を EXACT（大文字小文字を区別）で比較しました。
　hostname / user / password は設計書に値の記載が無い（E列・I列とも空欄、
　H列が「AIスコアリングヒアリングシート2部」）ため、monitor の API設定と同様に
　ヒアリングシート2部と資材を直接突合しています。

【確認1】AIScoringAPICall.properties の接続情報が
　　　　 5ファイル中4ファイルで PKGテンプレートのままです（最重要）
═══════════════════════════════════════════════
■ 事象
　対象5ファイルの hostname / user / password を比較したところ、
　お客様設定値が入っているのは 横東 aml02（東日本銀行）の1ファイルのみでした。

　　　　　　　　　横東aml01  横東aml02     陸道七aml01 陸道七aml02 陸道七aml03
　　　　　　　　　（横浜）   （東日本）    （北海道）  （七十七）  （北陸）
　　hostname      127.0.0.1  0371.caml.jp  127.0.0.1   127.0.0.1   127.0.0.1
　　user          user01     API_filter    user01      user01      user01
　　password      （同一）   （行別の値）  （同一）    （同一）    （同一）
　　判定          ×          ○             ×           ×           ×

　ヒアリングシート2部に記載の値（例：横浜 https://0384.caml.jp ／ APIfilter）
　とは一致していません。4ファイルの hostname / user / password は
　いずれも http://127.0.0.1:8081 ／ user01 ／ 同一パスワードで、
　パッケージ同梱の雛形と同じ内容と見られます。

■ 補足（配備ミスではなく設定作業漏れと推測する根拠）
　outputpath はスキーマ別に正しく振られています。
　　横東aml01 → C:/FileRCV/input_AI/aml01/
　　横東aml02 → C:/FileRCV/input_AI/aml02/
　　陸道七aml01/02/03 → 同 aml01/ aml02/ aml03/
　スキーマ別の雛形生成までは行われており、その後の接続情報の
　設定作業が aml02（東日本）以外で実施されていない、と考えられます。

■ 影響
　このままでは共同機構への API 接続が localhost に向くため、
　AIスコアリング連携が機能しません。

■ 確認依頼
　(1) 現地リリース資材として、この状態が正しいでしょうか。
　　　（出荷後に現地で設定する運用であれば、その旨ご教示ください）
　(2) 資材の採取元フォルダ名が「\API」か「\APICall」かもあわせて
　　　ご確認いただけますでしょうか。
　　　修正履歴 項番57（横東）／項番53（陸道七）（2026/06/22 阿部さん）で
　　　「\amlXX\API」→「\amlXX\APICall」へ改名されています。
　　　旧フォルダが残っている場合、そちらの古いファイルを採取している
　　　可能性があります。設定済の 横東aml02 がどちらのフォルダに
　　　あったかが判断材料になると思われます。

【確認2】AIScoringAPICall.properties の inputpath が
　　　　 設計書の記載と異なります（5ファイル共通）
═══════════════════════════════════════════════
■ 事象
　　設計書 I列：C:\common\tools\AIScoringExport\amlXX\export\
　　資材　　　：C:/common/tools/AIScoringExport/
　　（スキーマ名と export フォルダが付いていません）

　該当箇所　properties設定一覧(AML)
　　横東　　行169（aml01）／行186（aml02）
　　陸道七　行247（aml01）／行264（aml02）／行281（aml03）

■ 補足
　5ファイルすべてが同じ値のため、個別の設定ミスではないと考えています。
　プログラム側でスキーマ名／export を付加している可能性もあります。

■ 確認依頼
　設計書と資材のどちらが正でしょうか。
　設計書が正であれば資材修正、資材が正であれば設計書修正が必要と考えます。

【確認4】AIScoringImport.properties の突合対象（AML側／SIM側）
═══════════════════════════════════════════════
■ 事象
　同名ファイルが properties設定一覧(AML) と (SIM) の両方にありますが、
　connectstring の有効値が異なります。

　　AML側（横東 行192／陸道七 行287）
　　　E列（PKG標準）localhost:5432/amldb
　　　I列（調整後）（RDSエンドポイント）:5432/amldb
　　　J列　DBサーバではなくRDSにDB構築しているため
　　　→ 有効値は I列（RDSエンドポイント）

　　SIM側（横東 行175／陸道七 行253）
　　　I列が空欄
　　　→ 有効値は E列（localhost:5432/amldb）

　入手した資材には実際の RDS エンドポイントが設定されており、
　AML側の記載と整合しています。password も設計書 E列の値と一致しました。

■ 確認依頼
　(1) 今回の横展開の突合対象は AML側のみという理解でよいでしょうか。
　(2) 修正履歴 項番25「SimulationControl.properties の connectstring を
　　　RDSエンドポイントからローカル接続に変更」との関係もご教示ください。
　　　AIScoringImport.properties は RDS のままですが、意図的でしょうか。
