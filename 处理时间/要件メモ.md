2026/11/09 時点。阿部さんの指示・回答と、手元で確認できた事実をまとめたもの。

## 背景

- 障害「20260202_filter_業後処理長時間化に伴うフィルタリング漏れ及びユーザ取込漏れ」の再発防止対応。
- 格納先：`\\core-fs\Projects\International\CUST\NTTD(MEJAR)\90_保守管理\07_障害管理\20260202_filter_業後処理長時間化に伴うフィルタリング漏れ及びユーザ取込漏れ\13_再発防止対応\04_処理時間・テーブル件数監視\filter`
- テーブル件数の監視は対応済み（`テーブル件数転記ツール/`）。**処理時間の一覧化は未対応**で、今回これに着手する。

## 阿部さんの指示

1. 各タスクの開始時刻・終了時刻を抜き出す（上記フォルダの既存ファイルを参考にする）。
2. 特定のタスクについて、最も遅かった日と最も早かった日を取得する。その2日について、当日の各タスクの処理時間を抜き出す。
   - 「その日」は朝 7:00 のオンライン開始から始まる想定。**この時刻は変更の可能性あり**。
   - つまり 07:00〜翌 06:59 を1日として扱う。0時を過ぎてから終わる業後処理などは前日側に入る。
3. 対象はすべてのタスク。
4. 元データは `ev_app_YYYYMMDDHHII.log`。イベントビューアーの Application ログをエクスポートしたもので、全タスクのログが入っている。
   - 横東の例：`\\192.168.1.28\dev\統合AML\01開発\Library\15_顧客別ライブラリ\19_mejar\05_5行共同化更改\filter\持ち帰り\LogFiles\横東_LogFiles_20260529.zip\横東_LogFiles_20260529\Security\`
   - 毎日 22:39 ごろにエクスポートされている。1ファイル約 23MB。

## 既存の切り出し（前任者作成、2026/08/30）

- 仕分け方法：ログからタスクごとに開始ログ・終了ログの行を切り出し、曜日で仕分けている。
- ファイル名の prefix で曜日を表す（「あとで変えるかも」とのこと）。
  - `M`：第1月曜
  - `MTWTFS`：月〜金（第1月曜を除く）
  - `S`：日曜
- ファイル名は `M-01-1 オンライン開始処理_開始.txt` ／ `M-01-2 オンライン開始処理_終了.txt` の形式（`-1`＝開始、`-2`＝終了）。
- M のタスクは次の9件。
  - 01 オンライン開始処理
  - 02 二次バックアップ処理
  - 03 二次バックアップ強制停止処理
  - 04 オンライン停止処理
  - 05 リスト作成処理
  - 06 リスト反映処理
  - 07 業後処理
  - 08 環境初期化
  - 09 全量フィルタリング処理
- 中身の例：`2026-04-06 07:00:01 OCULUS-ICOM100001オンライン開始処理－オフライン終了チェックを開始します`
- 気になる点
  - M に `2026-06-08` が入っている。2026年6月の第1月曜は 06-01 なので、06-08 は第2月曜にあたる。
  - `M-06-1 リスト反映処理_開始.txt` が無く、終了ファイルしかない。

## ログ形式（スクリーンショットから）

wevtutil のテキスト形式。`Event[n]` ごとのブロックになっており、**新しいイベントが先頭**に来る。

```
Event[1]
  Log Name: Application
  Source: OCULUSBT
  Date: 2026-02-28T22:39:06.5660000Z
  Event ID: 999
  Task: N/A
  Level: 情報
  Opcode: 情報
  Keyword: クラシック
  User: S-1-5-21-…
  User Name: <ホスト名>\OCULUS01
  Computer: <ホスト名>
  Description:
OCULUS-I COM900100 長期保管用ファイルバックアップ処理を開始します。
```

- Description は次の行に書かれている。メッセージIDは `OCULUS-I COMnnnnnn` の形（`OCULUS-I` の後ろに空白あり）。
- 前任者の切り出しファイルでは `OCULUS-ICOM100001` のように空白が無い。切り出すときに空白を詰めたか、ログの種類が違う可能性がある。
- Date の末尾に `Z` が付いているが、**ログに表示されている時刻をそのまま使う**（2026/11/09 決定。時差の換算はしない）。
- ファイル名は `202603012239` なのに、先頭のイベント（エクスポート開始）の時刻は `02-28T22:39`。これも時刻表記の確認対象。
- 文字コードは未確認（UTF-16 か Shift_JIS）。

## 進め方（案）

- データは WorkSpaces から持ち出さない前提で、WorkSpaces 内で動くツールを作る（PowerShell 本体＋ .bat から起動）。
  - 開発は手元で行い、上記の形式に合わせたダミーデータでテストする。
- 処理の流れ
  1. 複数の ev_app_*.log を読み込む。
  2. 重複を除く（日次エクスポートの期間が重なるため）。
  3. タスクごとに開始・終了イベントを抽出する。
  4. 07:00 で日付を切る（時刻は設定値にする）。
  5. M／MTWTFS／S に仕分ける。
  6. 処理時間（終了 − 開始）を計算する。
  7. 一覧（CSV／Excel）に出力する。
  8. 指示2のとおり、最遅日・最速日の各タスクの処理時間を抜き出す。
