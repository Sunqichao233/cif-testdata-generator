# 処理時間抽出ツール

イベントビューアーのログ（`ev_xxx_YYYYMMDDHHII.log`）を複数まとめて読み込み、タスクごとに開始時刻・終了時刻・処理時間を一覧にするツールです。
障害「20260202_filter_業後処理長時間化」の再発防止対応で使います。

## 使い方

1. ログファイル、またはログが入ったフォルダを
   `ここにログファイル（またはフォルダ）をドラッグ＆ドロップしてください.bat` にドラッグ＆ドロップします。
   - フォルダを指定した場合は、中の `ev_app_*.log` をすべて読み込みます（サブフォルダも含む）。
   - 何も指定せずにダブルクリックした場合は、ツール直下の `入力\` フォルダを読み込みます。
   - ファイルを大量に選ぶとドラッグ＆ドロップできないことがあります。その場合はフォルダごと渡してください。
2. 結果は `出力\` に出力されます（毎回同じフォルダ）。

### 2回目以降の実行（追加）

- 同じ名前のファイルがある場合は、置き換えずに**更新**します。新しい日のログだけを渡せば、前回までの結果に追加されます。
- 読み込んだログは `出力\_蓄積\`（イベント.tsv／ログ範囲.tsv）に保存されます。次回は、保存したデータと今回のログを合わせて集計し直します。
  - 前回は「ログ不完全」だった日も、続きのログを渡せば完全な値になります。
  - 同じログを何度渡しても、二重に数えることはありません。
- `切り出し\*.txt` は、既にあるファイルの行を残したまま更新します。前任者のファイルを先に入れておいても、その行は消えません。同じ業務日の行がある場合は、今回の内容で上書きします。
- CSV（00〜03）は、蓄積データ全体から毎回作り直します。CSV を手で直しても次の実行で元に戻るので、手で直すときは別名で保存してください。
- **最初からやり直す**ときは、`出力` フォルダを削除してから実行してください。
- タスク定義.csv を変えたときも、蓄積データから集計し直すので、ログを渡し直す必要はありません。

PowerShell 5.1（Windows 標準）で動きます。インストールは不要です。

## 出力ファイル

| ファイル | 内容 |
|---|---|
| `00_メッセージ一覧.csv` | ログに出てきたメッセージの種類・件数・初回／最終日時、該当するタスク。タスク定義を調整するときに使う |
| `01_処理時間一覧.csv` | 業務日 × タスクごとの開始・終了・処理時間・備考（開始ログなし／ログ不完全／エラーログあり など） |
| `02_処理時間表_M.csv` ／ `_MTWTFS.csv` ／ `_S.csv` | タスク × 業務日 の処理時間表（区分別） |
| `03_最遅最速_<基準タスク>.csv` | 区分ごとに、基準タスクが最も遅かった日と最も早かった日の各タスクの処理時間を並べたもの。2日の差も出す |
| `切り出し\M-01-1 オンライン開始処理_開始.txt` など | 前任者の切り出しファイルと同じ形式。開始・終了に使ったログの行 |

CSV は UTF-8（BOM付き）なので、Excel でダブルクリックすればそのまま開けます。

## 判定のルール

- **業務日**：07:00 から翌日 06:59 までを1日として扱います。0時を過ぎてから終わった業後処理などは前日分に入ります。
- **区分**
  - `M`：第1月曜
  - `MTWTFS`：それ以外の平日（土曜もここに入れています。設定で変更可）
  - `S`：日曜
- **開始・終了**：`タスク定義.csv` のパターンを使い、その業務日で開始パターンに合う最初のログを開始、終了パターンに合う最後のログを終了とします。
- **重複**：日次のエクスポートは期間が重なっているので、同じ日時・同じ本文のログは1件にまとめます。
- **ログ不完全**：業務日の 07:00〜翌 07:00 をログが全部カバーしていない日です。読み込んだ期間の最初と最後の日に起こります。備考に「ログ不完全」と表示し、最遅・最速の判定対象から外します。
- **エラーログ**：そのタスクのログに `OCULUS-E` があれば、備考に件数を出します。

## 設定

`script\extract_time.ps1` の先頭で変更します。

| 項目 | 初期値 | 説明 |
|---|---|---|
| `$DayStart` | `07:00` | 業務日の開始時刻 |
| `$Source` | `OCULUSBT` | 対象のイベントソース |
| `$BaseTask` | `業後処理` | 最遅・最速を判定する基準タスク |
| `$CompareBy` | `終了時刻` | 最遅・最速の判定基準。`終了時刻` または `処理時間` |
| `$SaturdayClass` | `MTWTFS` | 土曜日の区分 |
| `$OutCharset` | `utf-8-bom` | 出力の文字コード。`932` にすると Shift_JIS |

## タスク定義.csv

```
No,タスク名,開始パターン,終了パターン
01,オンライン開始処理,^オンライン開始処理[−－-].*を開始します,^オンライン開始処理[−－-].*終了しました
```

- パターンは、メッセージ本文（`OCULUS-I COMnnnnnn` より後ろの部分）に対する正規表現です。
- 実ログの形式（横東の LogFiles で確認済み）
  - 開始：`タスク名−サブ処理 を開始します`（COM100001）
  - 終了：`タスク名−サブ処理 が正常終了しました`（COM100003）
- その業務日で、開始パターンに合う最初のログを開始、終了パターンに合う最後のログを終了とします。
- `[−－-]` はタスク名の直後の区切り文字です。「業後処理」と「業後処理（週末）」を区別するために入れています。
- 現在は15タスクを定義しています（01〜09 は前任者の番号に合わせ、10〜15 は実ログで見つかったタスク）。
- ファイルは UTF-8（BOM付き）で保存してください（「−」が Shift_JIS では正しく保存できないため）。
- タスクを増やすときは行を追加します。行頭が `#` の行は読み飛ばします。

## 実行時間の目安

横東の LogFiles（90ファイル・約2GB、2026/02/05〜05/28 の113業務日）で約12分。2回目以降に1ファイルだけ追加した場合は約3分です。
